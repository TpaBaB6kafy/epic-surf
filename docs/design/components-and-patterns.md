# EPIC: компоненты и композиции

Статус второго подхода: переиспользуемая библиотека реализована. [Реальный API, правила использования и ограничения](library-api.md) имеют приоритет перед названиями будущих компонентов ниже. Таблица владельцев текущей главной остаётся картой production, а не заявлением о её миграции.

Карта владельцев зафиксирована в первом подходе 2026-10-05, контракт реализован во втором. Геометрия задаётся [общим стандартом](layout-and-scale.md); оформление — [основами](foundations.md).

## Реальные владельцы главной

## Каскад стилей

HomeV2Page подключает home-v5-responsive.css, затем polish для уроков/поверхностей, mobile-finish, reviews, rental-desktop и desktop-scale. Кроме этого есть globals.css, CSS дочерних компонентов и module CSS hero. Финальный победивший стиль зависит от специфичности и места подключения, а не только от названия файла.

Перед переносом компонента проверить browser computed style и фактический query-container. Не брать первое совпадение в globals.css. У How более специфичный home-v5-how.css остаётся существенным на tablet; у галереи photo-gallery.css задаёт native scrolling и lightbox. Старые DOM-ветки в крупных wrapper-файлах могут существовать, но скрываться или никогда не достигаться. Удаление требует проверки вызовов и условий рендеринга.

## Контракт компонента библиотеки

Каждый компонент получает один паспорт:

1. Назначение и примеры, где его выбирать.
2. Семантика: button, link, article, heading, region, dialog; доступны только осмысленные variants.
3. Данные: EN/RU текст, фото/alt/framing, href или callback; содержание отделено от геометрии.
4. Геометрия: контейнер, padding/gap/radius, min/max, адаптивная раскладка.
5. Состояния: обычное, hover, active, focus-visible, выбранное; disabled/loading/error только где они имеют смысл.
6. Ограничения: длинная подпись, большой price, отсутствие фото/описания, число элементов.
7. Поведение: keyboard, touch, reduced motion, восстановление фокуса и scroll.
8. Пример кода и соответствующий образец в каталоге.
9. Источник и правила изменения: общие роли или рецепт конкретной композиции.

Каталог рендерит те же exports и token recipes, что доступны страницам. Не создавать параллельные "демо-кнопки" с отдельным CSS. Для визуальных примеров действия не должны отправлять реальную заявку или производить production analytics.

## Что выделено во втором подходе

| Реализованная единица | Роли / варианты | Граница ответственности |
| --- | --- | --- |
| PageFrame / ContentFrame | Общая stage/content geometry, readable column | Не копирует координаты каждой секции и не требует поддельного home-root |
| SectionHeading | Выразительный заголовок, локализованные роли | Уровень h1/h2/h3 задаётся страницей; визуальный variant не меняет смысл |
| Action | Primary coral, secondary graphite; button и link | Существующий обработчик приходит извне; loading/disabled не теряют доступность |
| IconControl | Круглая морская стрелка, компактный control | Размер цели и aria-label; стрелка не служит обычной большой CTA |
| Surface | Dark/paper/sea, отдельная роль тени | Информационная карточка не получает автоматически hover как кнопка |
| FramedPhoto | Cover, framing, radius recipe; arch отдельно | Сохраняет alt, пропорции рамки и кадрирование |
| FAQItem / FAQList | Закрыто/открыто, light surface | Реальные тексты и aria-controls; высота следует ответу |
| ReviewCard / ReviewRating | Paper card, arch avatar, compact summary | 4 строки, реальная full-review ссылка; рейтинг остаётся отдельной ссылкой |
| Filter + role=group wrapper | Обычный/выбранный, gallery role | aria-pressed и keyboard; не совмещать выбранное и disabled |
| Field / FormStatus | Label/help/error/disabled/loading | Новая утилитарная роль; родитель управляет валидацией и отправкой |
| Dialog | Booking/rental/photo use cases | Focus trap, Escape, scroll lock, close и возврат фокуса; внутренние flows сохраняются |

Выделять сначала самые повторяемые элементы. Не универсализировать целый HomeV2Page в один компонент с десятками переключателей. Не переносить трекинг и partner attribution в декоративную Surface.

## Секции: правила сборки

### Первый экран

Фото или видео, независимый бренд/заголовок, доступное основное действие и переход к следующему блоку. У текущей главной логотипы уже выполняют визуальную роль; для услуги нужна своя информационная иерархия. Media full-bleed не меняет края foreground content. Poster обязателен для видео.

### Процесс / преимущества

How служит рецептом "фото + короткое пояснение": два столбца карточек на широком экране, один на узком. Фото и текст связаны внутри карточки, подпись наложена на фото. Для обычных преимуществ без фото использовать спокойную раскладку и те же typography/surface роли, а не искусственно добавлять фотографию.

### Услуга и цена

Название, цена, описание, фото и CTA образуют одну композицию. Переключение изменяет весь набор данных и объявляет обновление. Для одной услуги навигационные стрелки не нужны. Число слов в заголовке и цена не должны требовать уникальных CSS координат. Пять существующих форматов уроков — обязательные content cases для проверки ServiceOffer.

### Каталог аренды

Общий широкий ContentFrame; число колонок выбирается по содержанию и ширине карточки. Board card связывает фото, характеристики, доступное действие. Rent открывает рабочий flow с нужной доской, ссылка на каталог сохраняет язык. Каталог не переносит круговое фото и бегущую строку главной автоматически.

### Текст с фото / подробный гайд

Длинный текст внутри readable column, фото/навигация/CTA в соседней области при достаточной ширине. На телефоне смысловой порядок сохраняется. Table, list, notice и media caption получают отдельные роли. Карта не мешает прокрутке. Не делать весь гайд узким и не превращать каждую фразу в карточку.

### Отзывы

Заголовок и рейтинг, согласованные карточки, проверенные авторы/фото, ссылка на полный текст. В текущем рецепте desktop имеет три карточки, 900–1199 px — два столбца с центрированной третьей, 700–899 px — один столбец; mobile — один. Волна описывается самостоятельным section-transition recipe и не обязательна для каждого блока отзывов.

### FAQ / галерея / завершающее действие

FAQ использует читаемые строки и ответы без фиксированной общей высоты. Галерея собирает альбомы из реальных снимков и сохраняет native vertical scroll. Завершающий CTA повторяет action hierarchy страницы; вторичные контакты не конкурируют с основным действием. Декоративный переход не закрывает край текста или controls.

## Шаблоны третьего подхода

| Тип | Стартовый порядок секций | Проверка содержания |
| --- | --- | --- |
| Услуга | Hero → кому подходит → процесс → форматы/цена → Included → отзывы → FAQ → CTA | Одна/несколько услуг; длинные EN/RU названия, booking и messenger |
| Аренда | Hero/условия → каталог → pickup/delivery → правила → отзывы → FAQ → CTA | Длинные характеристики, разные фотографии досок, конкретная доска в RentalModal |
| Посадочная | Hero → ценность → фото/процесс → предложение → доказательства → FAQ → CTA | Короткое содержание без копирования всех секций главной |
| Гайд | Hero → оглавление → текст/фото → условия/карта → заметки → связанная услуга → FAQ | Длинный текст, таблицы/списки, реальные состояния embed и mobile scrolling |

Это стартовые рецепты, допускающие перестановку по задаче. Готовая секция не означает обязательную секцию на каждой странице. Сначала проверяется демонстрационная страница; публичные маршруты меняются отдельным согласованным объёмом.
