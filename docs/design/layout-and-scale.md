# EPIC: стандарт композиции, масштаба и воздуха

Утверждён пользователем 2026-10-05 после просмотра RU/EN до и после. Применять при следующих изменениях главной, аренды, посадочных, партнёрских страниц и гайдов. Это общий стандарт, а не требование немедленно переделать все существующие страницы.

Полный контекст системы: [вход в документацию](README.md), [основы оформления](foundations.md), [компоненты и композиции](components-and-patterns.md). Этот файл остаётся нормативным источником геометрии. [Измеренный эталон](homepage-baseline.md) фиксирует текущую реализацию и её расхождения; его наблюдения не заменяют утверждённые правила.

## Что считаем эталоном

Текущая одобренная главная: выразительные реальные фото, крупные скругления, объёмные CTA, исходная палитра и собранная композиция с воздухом. Улучшать существующую структуру, не заменять её новой по собственной инициативе. Новая страница наследует масштаб и визуальный язык, но получает подходящую её содержанию раскладку.

Реализация эталона: [home-v5-desktop-scale.css](../../app/components/home-v2/sections/home-v5-desktop-scale.css), подключённый в [HomeV2Page.jsx](../../app/components/home-v2/HomeV2Page.jsx). Важны итоговые вычисленные стили, а не более ранние правила в globals.css.

## Общая ширина на десктопе

На ширинах от 1200 CSS px использовать:

- Композиция: S = min(94vw, 2160px).
- Основной контент: C = S × 0.832.
- Поля внутри композиции: по 8.4% S; общий отступ контента от края окна: (W − C) / 2.
- Основные заголовки, карточки, каталоги, сетки, медиаблоки и подвал должны опираться на общие края C. У шапки может быть более широкая рамка S, как на главной.
- Фоны, видео hero, текстуры и переходы между секциями могут занимать всю ширину экрана. Их ширина не должна раздувать весь интерфейс.

| Окно, CSS px | Композиция S | Контент C | Поле контента с каждой стороны |
| --- | --- | --- | --- |
| 1200 | 1128 | 939 | 131 |
| 1440 | 1354 | 1126 | 157 |
| 1920 | 1805 | 1502 | 209 |
| 2560 | 2160 | 1797 | 381 |
| 3200 | 2160 | 1797 | 701 |

Значения округлены. Учитывать реальную ширину браузера и полосу прокрутки, а не диагональ монитора. Оценивать прежде всего при браузерном масштабе 100%.

Утверждённый предел — 2160 px. Промежуточный вариант 2000 px оказался тесным; исходное неограниченное увеличение с экраном — чрезмерно крупным. Не возвращать эти варианты как новый стандарт.

Для нового каркаса можно использовать эквивалентные общие токены:

~~~css
@media (min-width: 1200px) {
  .epic-page {
    --epic-stage-width: min(94vw, 2160px);
    --epic-stage-unit: calc(var(--epic-stage-width) / 100);
    --epic-content-width: calc(var(--epic-stage-width) * .832);
  }
  .epic-page .epic-content {
    width: var(--epic-content-width);
    margin-inline: auto;
  }
}
~~~

Это рецепт, а не дополнительный CSS-файл для слепого подключения. При реализации переиспользовать имеющиеся токены/каркас либо общий компонент, если он действительно нужен нескольким страницам. Не плодить разные пределы ширины для каждой секции.

## Аренда и посадочные

Каталог досок, hero с фото, отзывы и сетки посадочной используют общий широкий каркас. Число колонок и размер отдельных карточек выбирать по содержанию; не растягивать одну карточку на весь широкий контейнер.

Длинный текст держать в читаемой колонке примерно 60–68ch внутри общего каркаса. Узкая текстовая колонка допустима; узкая вся страница — нет. Дополнительная колонка может содержать фото, навигацию, пояснение или CTA, если они нужны пользователю.

Прежний предел 1248/1280 px у всего лендинга не переносить в новый редизайн как эталон. При этом не менять существующую страницу только ради этого документа, если она вне текущей задачи.

Не импортировать стили главной на посадочные через поддельный data-home-v2-root: использовать их собственный корень и общую геометрию без утечки стилей.

## Вертикальный ритм

Разделять три вещи: внутренние поля карточки, промежутки между элементами секции и расстояние до соседней секции/декора. Не создавать внешний воздух пустотой внутри карточек.

Для новых обычных секций ориентир внешних отступов — 64–96 px на десктопе; рядом с крупной декоративной композицией может требоваться 96–144 px видимого зазора. Это исходные ориентиры для визуальной проверки, не одинаковые обязательные поля всех секций.

Одобренные конкретные значения главной:

- Отзывы: верхний padding секции 80 px; это дополнение к собственной нижней геометрии прогноза, а не полное расстояние от камеры до заголовка.
- От карточек отзывов до ближайшего видимого верхнего края коллажа — примерно 144 px. Резервировать высоту видимой волны отдельно: просто padding-bottom: 144px не заменяет её геометрию.
- От заголовка/рейтинга до ряда отзывов — 32 px.
- Карточки отзывов одинаковой высоты, максимум четыре строки текста с многоточием и ссылка на настоящий полный отзыв. Не добавлять пустую высоту ради заполнения секции.
- How It Works: min-height карточки = 17.222222 × единица S/100; фото = 16.25 × единица S/100. На 1440 px карточка около 233 px, на 2560 px — 372 px. Это пропорции этого блока, не размер всех карточек сайта.

При сужении общей композиции отдельно проверять высоту и кадрирование фотографий. В предыдущей итерации ширина карточки How It Works почти сохранилась, а высота уменьшилась слишком сильно — такой эффект не повторять.

## Масштаб элементов и типографики

Не использовать CSS zoom, transform: scale всей страницы или совет посетителю увеличить масштаб браузера как исправление макета. Ограничивать геометрию и типографику отдельно.

Важно для cqw: единица относится к content box ближайшего query-контейнера. Если контейнер уже имеет боковой padding, его cqw может быть меньше единицы общей композиции. Высоту, рассчитанную от S, задавать через общий stage-unit, не через случайный вложенный контейнер.

Сохранять реальные фото и их пропорции. Декоративные края могут заполнять широкий фон отдельно, но солнце, логотипы и лица не должны растягиваться. Коллаж отзывов использует исходный WebP, пропорциональный центр и расширенные края; не заменять это общим растягиванием картинки.

Текущие размеры как ориентиры:

- Основные заголовки секций: 32–44 px на десктопе; hero может иметь отдельный более крупный заголовок.
- Текст отзывов: 18 px, line-height и четырёхстрочный предел сохраняются. Основной текст других блоков обычно 18–24 px по роли; не увеличивать всё только из-за большого окна.
- Подписи основных CTA: 16–22 px; размеры растут до ограниченного максимума. На главной у крупных CTA/стрелок предел высоты 84 px, не требование сделать все кнопки высотой 84 px.
- Вторичные ссылки, авторы и метаданные могут быть меньше основного текста, сохраняя читаемость.

## Карточки и кнопки

Сохранять действующую палитру и шрифтовой характер. Белые карточки допустимы там, где уже одобрены, например в отзывах; не превращать тёмные блоки в белый шаблон.

Основная CTA — коралловая объёмная капсула с текущим градиентом, верхним бликом/границей и нижней тенью, как Book Now и Rent Now. Вторичная CTA — серая/графитовая с тем же характером объёма и читаемым текстом. Не делать обе кнопки одинаково акцентными без причины.

Сохранять понятные hover, pressed и keyboard-focus состояния. Кнопки одной строки имеют согласованные высоту, поля и размер текста. Скругления четырёх углов обычных карточек одинаковы; асимметрию вводить только при явном композиционном замысле, а не случайным набором радиусов.

Не копировать тень кнопки на портрет: аватары отзывов — реальные фотографии в форме арки, не элементы управления. Рейтинг Google Maps и его одобренную тень сохранять, если задача их не касается.

## Мобильная версия и планшет

Десктопный стандарт начинается с 1200 px. Изменение desktop-геометрии само по себе не должно менять одобренный mobile/tablet.

Для новых мобильных страниц сохранять тот же характер, но собирать отдельную читаемую композицию. Не уменьшать весь desktop пропорционально до телефона. Длинные тексты и русский перевод должны свободно переноситься.

Проверять области нажатия минимум 44×44 px, нижние плавающие кнопки чата, sticky-шапку и доступность всех управляющих элементов. Перекрытия допустимы, если они соединяют композицию и не закрывают текст/кнопки. Карты и iframe не должны перехватывать обычную прокрутку страницы без явного включения взаимодействия.

## Проверка перед показом результата

1. Снять исходные скрины затронутой страницы до изменений.
2. Проверить EN/RU на 390, 1024, 1440, 1920 и 2560 CSS px; при общих контейнерных правках также 1200 и 3200 px. Для нового mobile дополнительно 320/360 px.
3. Смотреть полную страницу и крупные фрагменты: края сеток, размер шрифта, пропорции фото, видимый зазор до декора, плотность карточек. Одного узкого окна на ноутбуке недостаточно.
4. Проверить overflow, переносы RU/EN, интерактивные состояния, существующие формы/ссылки и reduced motion, если есть анимация. Для правки только MD браузерные тесты не требуются.
5. Снять сопоставимые до/после при 100% и одинаковых размерах окна. Отдельно указывать фиксацию внешних виджетов/видео в QA.
6. Коротко описать изменения и дать ссылки на сравнение. Коммит/публикация — по запросу пользователя.

Референс одобренной итерации: локальные снимки в output/desktop-scale-2026-10-05/refinement. Они вспомогательные и могут отсутствовать в другой рабочей копии; нормативные значения сохранены выше, а реализация доступна в исходниках.

## Приоритет и история

Текущая задача пользователя имеет приоритет. Этот стандарт заменяет прежние рекомендации по масштабу/композиции в старых брифах, Figma-handoff и отчётах итераций. Не использовать старый QA-лог как предписание восстановить прежний макет.

Старый Poster System v1 перенесён в [архив](../archive/poster-system-v1/README.md). Его референсы не разрешают перенос чужих изображений, логотипов или палитр на сайт.

Документ задаёт правила для последующей работы, а не утверждает, что все страницы уже им соответствуют. Новое утверждённое изменение стандарта вносить сюда и в общую реализацию, вместо создания ещё одного конкурирующего MD.
