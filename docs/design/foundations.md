# EPIC: основы оформления

Дата фиксации: 2026-10-05. Основа — утверждённая главная; [геометрия и масштаб](layout-and-scale.md) остаются единым нормативным источником. Этот документ дополняет его ролями оформления. Фактические особенности отдельных секций приведены в [эталоне](homepage-baseline.md); спорные различия — в [решениях](decisions-and-rollout.md).

## 1. Визуальный характер

Реальные фотографии с выразительным кадрированием, крупные мягкие формы, графитовые и морские поверхности, коралловый акцент, объёмные кнопки. Контент имеет общие края и контролируемый масштаб. Фон и декоративные переходы могут быть шире контента. Текст, лица и действия сохраняют читаемость и пропорции.

Чередование плотных и спокойных секций определяется содержанием. Отзывы могут быть светлыми; из этого не следует, что все карточки сайта должны стать светлыми. Коллаж, волна или наложение служат конкретной композиции и не добавляются автоматически в каждый блок.

Старые объявления Bebas Neue, Inter и Arial Black не назначать автоматически на новые элементы. Встроенный в логотип рисунок не является шрифтом для обычных заголовков.

Указанный в CSS font-family не доказывает, какой шрифт рисует кириллицу. Проверять файл и фактические glyph fonts. При выделении библиотеки явно задавать языковые роли; замену кириллического шрифта не проводить скрыто.

Размеры назначаются по роли и ограничиваются отдельно от ширины страницы. Общие диапазоны — в layout-and-scale.md; точные образцы на 390/1024/1440/2560 — в homepage-baseline.md. 26 px у EN описания урока, 32.4 px у FAQ и 36 px у событий на широком экране являются особенностями текущих рецептов, а не общим body token.

Длинный текст новой страницы получает читаемую колонку внутри общего каркаса. Высота текстового блока следует содержанию. Для новых текстов не копировать ручные EN переводы строк и фиксированные высоты из Figma-handoff.

## 4. Отступы и формы

Отдельные роли: page-gutter, section-space, heading-gap, grid-gap, card-padding и decorative-clearance. Внешний воздух не создаётся пустотой внутри карточки. Для каждой композиции описывать, где измеряется зазор: от рамки блока или видимого края картинки/волны.

Обычная карточка имеет согласованные четыре угла. Скругление следует роли поверхности; радиус фото урока, арки аватара и круглого control не заменяется единым card-radius.

Текущие образцы на телефоне 390 px:

| Поверхность | Радиус |
| --- | --- |
| Карточка How | 44 px |
| Фото How | 48 px |
| Фото урока | 70 px |
| Панель описания урока | 50 px |
| Отзыв | 40 px |
| Событие / плитка галереи | 32 px |
| CTA и фильтр | Капсула, 999 px |
| Круглая стрелка / badge | 50% |
| Аватар отзыва | 44 px 44 px 18 px 18 px; 88×104 px |

На desktop часть радиусов зависит от query-container; на 2560 px фото урока имеет 240 px, карточка How 124.8 px, галерея ограничена 96 px. Это отдельные рецепты. При извлечении использовать их реальные контейнеры: 1cqw после бокового padding может отличаться от 1% композиции. Значения этапа 1 не являются предложением добавить ещё один CSS слой.

## 5. Объём и границы

Три различимые роли: управляющий элемент, информационная поверхность, фотография. Тень кнопки не переносится на аватар. Декоративная SVG-поверхность получает drop-shadow по силуэту; CSS-карточка — box-shadow по своей рамке.

Текущий общий рецепт информационной поверхности:

```css
inset 0 1px 0 rgb(255 255 255 / 12%),
0 5px 0 rgb(0 0 0 / 14%),
0 18px 28px -12px rgb(0 0 0 / 30%)
```

Текущая коралловая CTA:

| Состояние | Тень | Перемещение |
| --- | --- | --- |
| Обычное | inset 0 2px 1px #FFFFFF4D; 0 5px 0 #4A302C; 0 14px 22px -8px #00000061 | Нет |
| Hover | inset 0 2px 1px #FFFFFF59; 0 8px 0 #4A302C; 0 18px 26px -8px #00000061 | Вверх 3 px |
| Pressed | inset 0 1px 3px #0000001F; 0 1px 0 #4A302C; 0 5px 9px -4px #0000003D | Вниз 4 px |

Граница CTA: 3 px, #4A302C. У графитовой CTA другие цвета границы/нижней тени. Более компактные controls шапки и фильтры используют имеющиеся --epic-raised-shadow / hover / pressed. Это отдельная роль, не уменьшенная копия большой CTA.

В библиотеке тень и градиент должны задаваться общей ролью, а не копироваться строками в каждую новую страницу. Не удалять собственные блики и границы фотографий при замене поверхности.

## 6. Действия и состояния

Основная CTA — коралловая. Вторичная — графитовая, с сопоставимой геометрией в одной группе. Ссылка на другой маршрут остаётся ссылкой; запуск модального окна остаётся кнопкой. Слой декора не перехватывает нажатие.

Фокус должен быть видимым на текущем фоне. Текущие варианты: коралловая обводка 3 px с внешним отступом 4–7 px; у галереи мятная внутренняя обводка. Конкретный вариант фиксируется в паспорте компонента. Не объявлять единую обводку до проверки на всех поверхностях.

Минимальная интерактивная область новой библиотеки — 44×44 px. Существующие более маленькие элементы отмечены отдельно; их текущий размер не становится эталоном новых controls. Disabled, loading и error не показаны для всех главных CTA — библиотека должна добавить осмысленные состояния, не выдавая их за извлечённые из главной.

Варианты подписей обязаны выдерживать русский текст. На телефоне у событий уже есть короткие подписи, у Included — отдельный короткий текст; полный смысл должен сохраняться.

## 7. Фото, декор и слои

Фото не растягивается: cover внутри заданной рамки, contain в полноразмерном просмотре. Для каждого снимка доступны собственные x/y/scale через GalleryFramingProvider и photo-framing data. При переиспользовании сохранить кадрирование по слоту; универсальное object-position:center не заменяет выбранный кадр.

Слой фона располагается отдельно от контента; декоративные изображения имеют пустой alt, aria-hidden и не перекрывают controls. Рамка остаётся неподвижной при настройке масштаба фото. Перекрытие подписи с фото и CTA с панелью описания — описанные рецепты, а не общий отрицательный margin для всех карточек.

Коллаж отзывов сохраняет центральную пропорциональную часть и расширяет только края. Мобильный вариант имеет собственную геометрию. Полноэкранное видео использует отдельные poster/кадрирование для телефона; логотип остаётся независимым слоем.

## 8. Адаптивность и движение

Основная граница свободной сетки и ограниченной desktop-композиции — 1200 px. У отдельных рецептов есть собственные границы: 700 px для мобильных композиций, 900 px для hero-media/отзывов, 1000 px для How. Все границы перечислены в карте компонентов. Нельзя заменить их одним breakpoint без визуального сравнения.

На телефоне композиция перестраивается, текст свободно переносится, главные действия доступны рядом с соответствующим содержанием. Карта принимает взаимодействие после явного включения; обычная вертикальная прокрутка сохраняется. Lightbox сохраняет Escape, клавиши стрелок, возврат фокуса и свайп.

Обратная связь CTA: около 160 ms, ease; hero opacity 450 ms; lightbox имеет собственный вход/выход 380/260 ms. Hover применяется при hover:hover и pointer:fine. Не переносить hover-перемещение на touch.

Reduced motion оставляет смысл и оформление, убирая перемещение и необязательное видео. У текущей сцены заката используется статический тёплый вариант. Галерея сохраняет доступ к фото без анимации. Полные контракты движения проверяются во втором подходе вместе с интерактивными компонентами.
