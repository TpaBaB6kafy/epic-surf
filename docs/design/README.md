# EPIC Design System

**Пилот уроков пересобран по выбранному пользователем первому макету.** Предыдущая композиция отклонена; новый фото-шаблон и компоненты описаны в [service-template.md](service-template.md). Выбор макета не является разрешением публикации или массового переноса остальных страниц.

Третий подход: первый проверяемый шаблон услуги, 2026-10-05. Источник визуального языка — текущая утверждённая главная EN/RU. Общие компоненты реализованы в `app/components/design-system`, каталог — `/design-system`. Старый Poster System остаётся архивным материалом; первый публичный пилот — уроки EN/RU. Следующие пилоты — аренда и гайд.

## Как пользоваться системой

Для новой страницы сначала определить её задачу и подобрать композицию: услуга, аренда, посадочная или гайд. Затем выбрать секции, заполнить EN/RU и фото, проверить адаптивность и действия. Не переносить координаты главной в другую страницу целиком.

Общие роли относятся ко всему сайту. Рецепт конкретной секции применяется только к соответствующей композиции. Измеренные значения — свидетельство текущей реализации; они не отменяют нормативные правила и не делают все исторические различия обязательными.

Новая роль или компонент должны получить описание назначения, варианты, ограничения содержания, состояния, EN/RU и адаптивные примеры. Одно утверждённое изменение обновляет соответствующее правило и общую реализацию. Не создавать альтернативный стандарт в новом брифе.

## Что создано в первом подходе

- Инвентаризация реальных владельцев главной и каскада стилей.
- Основы оформления и границы между общими ролями и авторскими композициями.
- 28 измерений: EN/RU × 320, 360, 390, 699, 700, 899, 900, 1024, 1199, 1200, 1440, 1920, 2560, 3200 CSS px.
- 14 полных снимков и крупные фрагменты ключевых секций.
- Реально используемые Chromium шрифты, включая кириллические fallback, а не только CSS font-family.
- Список решений для библиотеки и критерии завершения оставшихся подходов.

## Что создано во втором подходе

- Один реестр tokens для runtime и таблицы каталога.
- Каркас, заголовки, поверхности, primary/secondary actions, icon controls, filters и фотографии.
- FAQ, поля, статусы и native dialog с keyboard/focus поведением.
- Композиции процесса, услуги/цены, Included, отзывов/волны, галереи и завершающего CTA.
- Каталог EN/RU: состояния, размеры, код для копирования, адаптивные iframe с реальным viewport.
- API и воспроизводимая браузерная проверка `scripts/qa-design-system.mjs`.

## Где смотреть

Новый каталог с запущенным dev-сервером: [RU](http://localhost:3000/design-system?lang=ru), [EN](http://localhost:3000/design-system?lang=en). Его демонстрационные действия не отправляют заявки. Каталог не индексируется, не входит в sitemap и не подключает production analytics.

Эталон первого подхода: локальный [просмотр снимков](../../output/design-system-baseline-2026-10-05/index.html), [обзор ключевых секций](../../output/design-system-baseline-2026-10-05/contact-sheet.png) и [полные измерения](../../output/design-system-baseline-2026-10-05/baseline.json). Эти артефакты лежат в output и не входят в код сайта. Краткий эталон сохранён в документации и воспроизводится инструментами ниже.

С текущим dev-сервером:

```powershell
node scripts/capture-design-baseline.mjs
node scripts/render-design-baseline.mjs
```

Можно задать EPIC_BASELINE_URL и EPIC_BASELINE_OUTPUT. Снимки используют reduced motion и подписанные заглушки внешних iframe; это фиксация стиля, а не проверка внешних сервисов или бронирования. Библиотека отдельно проверяет обычную и уменьшенную анимацию во втором подходе.

## Проверка второго подхода

[Итоговый отчёт](library-validation.md): production build, lint, 32 проверки поведения, 28 экранов EN/RU, сравнение главной с эталоном и ограничения внешних аватаров.

## Границы работ

В первом подходе внешний вид и поведение сайта не меняются. Во втором созданы общие компоненты и каталог на их основе; существующие публичные страницы сохраняют свои реализации. В третьем проверяется сборка демонстрационных шаблонов и выводится из использования старый каталог. Миграция существующих публичных страниц, commit, push и deploy — отдельные действия в согласованном объёме.

## Первый пилот третьего подхода

[Шаблон услуги](service-template.md): действующие уроки RU/EN, схема данных, API, инструкция следующей сборки и ограничения. [Проверка пилота](service-pilot-validation.md) фиксирует результат и локальные снимки. В каталоге раздел «Сборка» содержит переход к действующей странице.
